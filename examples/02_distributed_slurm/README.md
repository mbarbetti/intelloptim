# Example 02 — Distributed evaluation on SLURM

Demonstrates running a parallel intelloptim study across many SLURM
array-job tasks. Each task is an independent evaluator that contributes
trials to a single shared study on the server.

## What this shows

- Registering an objective with `@intopt.objective(..., study_spec={...})` so
  the evaluator CLI can join the study without extra flags.
- Using `submit.py` (the *driver*) to create the study up-front and render
  the sbatch template from `deploy/slurm/worker-evaluator.sbatch.j2`.
- Running `intelloptim-worker evaluator` as a SLURM array job.
- Token security: the token is never written into the sbatch script; SLURM
  inherits `INTELLOPTIM_TOKEN` from the submission environment.

## Files

| File | Purpose |
|------|---------|
| `objective.py` | Branin objective registered with `@intopt.objective` + study spec metadata |
| `submit.py` | Driver: creates study, writes `spec.json`, renders + optionally submits sbatch |
| `spec.json` | Generated by `submit.py` — the `StudyResolveRequest` payload |
| `logs/` | Created at submit time; SLURM writes per-task stdout/stderr here |

## Prerequisites

1. An intelloptim server is running and reachable from the login node.
2. `conda activate intelloptim` (or whatever your HPC conda env is named).
3. `INTELLOPTIM_URL` and `INTELLOPTIM_TOKEN` are set in the environment.

## Quick start

```bash
# On the login node
export INTELLOPTIM_URL=https://intelloptim.hpc.example.com
export INTELLOPTIM_TOKEN=$(cat ~/.config/intelloptim/token)

# Inspect the rendered sbatch script (no submission yet):
python examples/02_distributed_slurm/submit.py \
    --n-workers 20 \
    --n-trials-per-worker 50 \
    --time 02:00:00 \
    --partition cpu \
    --conda-base /opt/miniconda3

# Submit:
python examples/02_distributed_slurm/submit.py \
    --n-workers 20 \
    --n-trials-per-worker 50 \
    --time 02:00:00 \
    --partition cpu \
    --conda-base /opt/miniconda3 \
    --submit
```

The study accepts trials from all 20 workers concurrently. Each worker runs
`intelloptim-worker evaluator` which calls `/ask` → computes Branin →
calls `/tell` in a loop.

## Running locally (no SLURM)

Run any number of evaluator processes in parallel from separate terminals:

```bash
# Terminal A
intelloptim-worker evaluator \
    --server http://127.0.0.1:8000 \
    --import examples/02_distributed_slurm/objective.py:branin \
    --n-trials 25

# Terminal B
intelloptim-worker evaluator \
    --server http://127.0.0.1:8000 \
    --import examples/02_distributed_slurm/objective.py:branin \
    --n-trials 25
```

Both processes will join the same `slurm-demo-branin` study automatically
because the study identity is content-addressed (hash of token + spec).

## Adapting to your own objective

1. Create `my_pkg/objectives.py` with your objective decorated as:

   ```python
   import intelloptim as intopt

   @intopt.objective(
       "my-study",
       study_spec={
           "name": "my-study",
           "direction": "minimize",
           "sampler": {"kind": "tpe"},
           "parameters": [
               {"kind": "float", "name": "lr", "low": 1e-5, "high": 1e-1, "log": True},
           ],
           "pruner": {"kind": "nop"},
       },
   )
   def my_objective(trial: intopt.Trial) -> float:
       lr = trial.suggest_float("lr", 1e-5, 1e-1, log=True)
       return train_and_evaluate(lr)
   ```

2. Submit with:

   ```bash
   python examples/02_distributed_slurm/submit.py \
       --import my_pkg.objectives:my_objective \
       --submit
   ```

   Or pass `--spec-file spec.json` if you prefer to keep the study spec
   separate from the objective module.

## SLURM template variables

The template `deploy/slurm/worker-evaluator.sbatch.j2` accepts:

| Variable | Default | Description |
|----------|---------|-------------|
| `job_name` | `intopt-eval` | `#SBATCH --job-name` |
| `n_workers` | `10` | Array size (`--array=1-N`) |
| `max_concurrent` | `n_workers` | Throttle (`--array=1-N%M`) |
| `time_limit` | `04:00:00` | `#SBATCH --time` |
| `mem` | `4G` | `#SBATCH --mem` |
| `cpus` | `1` | `#SBATCH --cpus-per-task` |
| `partition` | *(unset)* | `#SBATCH --partition` |
| `account` | *(unset)* | `#SBATCH --account` |
| `log_dir` | `logs` | stdout/stderr path |
| `conda_env` | `intelloptim` | Conda environment name |
| `conda_base` | `/opt/conda` | Conda base directory |
| `server_url` | *(required)* | `INTELLOPTIM_URL` in the job |
| `import_spec` | *(required)* | `module:callable` or `/path/file.py:callable` |
| `spec_file` | *(unset)* | Path to `spec.json` (optional) |
| `n_trials` | `50` | Trials per worker |
